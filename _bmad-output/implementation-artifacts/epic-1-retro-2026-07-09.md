## Challenges

### 1. CI/Shell Quality Gaps (Stories 1.3 and 1.4)

Five separate CI quality issues caught in code review:
- `mapfile` used without explicit `shell: bash`
- `git diff` errors silenced with `2>/dev/null`
- Missing `--diff-filter=R` for renamed files
- No `timeout-minutes` on workflow job
- `enforce_admins: false` defaulted silently

**Root cause:** CI/YAML files were not reviewed with the same defensive discipline as application code during development.

### 2. Documentation Drift (All 4 Stories)

Every story had at least one documentation contradiction in review:
- Out-of-Scope sections not updated when scope changed mid-story
- Present-tense claims about features not yet active
- Hardcoded values (timestamps, real repo path) where placeholders were intended

**Root cause:** Documentation updates were treated as secondary to functional delivery rather than part of the definition of done.

### 3. No Git Baseline From Day One

All four stories used `baseline_commit: NO_VCS`. Code reviews diffed against `/dev/null` instead of a real baseline, making incremental change tracking harder than necessary.

**Resolution:** Aaron created the initial commit on 2026-07-09. All Epic 2 stories will use real commit SHAs.

### 4. "Shipped vs Deployed" Gap

Epic 1 was marked done before it was deployed. CODEOWNERS and branch protection were inert until Aaron took admin action on 2026-07-09. The gap was not clearly communicated until the retrospective.

---

## Key Insights

1. **The governance pipeline needs GitHub to be real.** The local validator works anywhere; CODEOWNERS and branch protection only activate on GitHub. Future epics should have an explicit "activation checklist" for any GitHub-dependent deliverables.

2. **CI files are infrastructure and deserve infrastructure-level review.** Shell portability, error handling, and security defaults in `.github/workflows/` should be checked as systematically as application logic.

3. **Documentation drift compounds.** Out-of-Scope sections that aren't updated become incorrect documentation. Each story should update all affected documentation sections as part of its completion criteria.
