## What We Built

Epic 2 delivered the post-merge publication pipeline and the pre-merge conflict gate:

- **Sidecar generator** (`scripts/generate_jsonld.py`) — JSON-LD sidecars for every context document, wired into `.github/workflows/build-index.yml`
- **Conflict detector** (`scripts/detect_conflicts.py`) — blocking PR-time conflict detection with tunable threshold, integrated into `.github/workflows/pr-validate.yml`
- **Domain-owner override + audit logging** — CODEOWNERS-based authorization, append-only audit records under `docs/_audit/conflict-overrides/`
- **Index builder** (`scripts/build_index.py`) — deterministic full-snapshot `index/index.json` + `index/build-manifest.json` with freshness SLA and shared `build_manifest_id`

## Successes

1. **Reuse-first architecture held throughout the epic.** Story 2.2 reused 2.1's CLI patterns; 2.3 extended 2.2's detector instead of duplicating it; 2.4 reused sidecar output directly as index input. No duplicated parsing/validation logic anywhere in the epic.
2. **Security discipline was consistent.** `yaml.safe_load()` used everywhere, called out explicitly as an OWASP deserialization guard, never regressed.
3. **Code review caught real correctness bugs, not just style.** Notable examples: 2.2's contradiction score moved from a hardcoded `0.70` to real Jaccard similarity with sentence-scoped negation matching; a `NaN`-threshold bypass was caught; 2.3 caught an override path that skipped document-error checks; 2.4 caught `status: draft` documents being miscategorized as `active`.
4. **Git-first baseline lesson from Epic 1 was fully applied** — every story used a real commit SHA.
5. **Test coverage grew substantially** — 82 tests at epic close vs. 11 at the end of Epic 1.

## Challenges

### 1. Recurring, unresolved CI/infrastructure debt

The same deferred items were flagged in Story 2.2's review, re-flagged as "pre-existing" in 2.3's review, and again in 2.4's review, without ever being fixed:
- No `permissions:` block on workflow jobs (least-privilege gap)
- No `actions/setup-python`/PyYAML install step in CI (silent reliance on the runner image having PyYAML preinstalled)
- `/tmp` vs `$RUNNER_TEMP` inconsistency for changed-docs file lists
- `cat "${REPORT_PATH}"` masking the real exit code on failure

**Root cause:** Deferred items were treated as a permanent backlog rather than a queue that closes. Epic 1's action item to apply CI/infrastructure review discipline reduced *new* issues but didn't retire *existing* ones.

### 2. Conflict-detection test strategy never formalized

Epic 1's retro committed Murat to defining a test strategy for probabilistic conflict detection before Story 2.2. No dedicated artifact was produced — the strong test coverage that resulted (Jaccard similarity, sentence-scoped negation, boundary values) emerged reactively through code review rather than from an upfront plan.

### 3. `contentStatus` schema.org mismatch left unresolved through the epic it was deferred to

Story 2.1 flagged that `contentStatus` isn't a real schema.org term (`schema:creativeWorkStatus` is correct) and explicitly deferred the fix "pending Story 2.4 + Epic 3 consumer updates." Story 2.4 came and went without addressing it. The decision now rolls directly into Epic 3, whose Go retrieval API will be the first real consumer of this field.

### 4. Pipeline validated only by unit tests, never by a real merge to `main`

All of Epic 2's deliverables are GitHub Actions workflows (`build-index.yml`, `pr-validate.yml`). Unit tests validate script logic but cannot validate that the workflow actually executes correctly against a real merge. Confirmed during this retrospective: **no `index/` directory exists anywhere in the repository** — `build_index.py` has never produced `index/index.json` or `index/build-manifest.json` against real content. This is the same "shipped vs. deployed" gap identified in the Epic 1 retrospective, recurring in a more consequential form (Epic 3 depends on these artifacts existing).

---

## Key Insights

1. **GitHub Actions workflows need real-trigger verification as part of "done," not just unit tests.** Unit-testing script logic in isolation gave false confidence that the pipeline worked; it has never been proven end-to-end.
2. **Deferred items need a closing mechanism.** An item flagged "pre-existing, deferred" for the second time should become a required fix in the next story rather than a permanent fixture.
3. **Contract-breaking decisions deferred to "a future story" need an explicit owner and trigger, or they get deferred again.** The `contentStatus` fix was deferred to "Story 2.4," which passed without resolving it.

## 🚨 Significant Discovery

Epic 2's publication pipeline (sidecar + index + manifest) has only been validated by unit tests and local smoke runs — never by a real merge to `main`. `index/index.json` and `index/build-manifest.json` do not exist in the repository. Epic 3 Story 3.1 (retrieval API) has no artifact to query against.

**Epic update recommendation:** Do not begin Epic 3 story creation until the publication pipeline has been proven end-to-end against a real merge and produces the expected artifacts.
